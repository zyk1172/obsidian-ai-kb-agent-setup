# v3 迁移：旧资料保留，默认停止采用

## 改版目标

多个 Agent 共享一份可审阅的长期背景。模型能力增强后，减少固定阅读顺序和重复说明，把精力放在来源、复用价值、时效和共享更新上。

旧笔记不会因“重新索引成功”而获得有效性。没有治理记录的旧笔记全部是 unreviewed，默认检索没有片段，默认 get 不返回正文。历史仍可显式读取。需要验证过时内容时，优先检查原项目、当前配置和实际服务，再决定重写或标为废弃。

## 切换步骤

1. 记录所有客户端当前 launcher/服务版本和配置位置。备份服务脚本、依赖声明与 launcher，私有 env 只在本地安全备份，不能提交到仓库。
2. 记录受管 `敏感信息.md` 及变体的 SHA-256 和 mtime。只计算摘要，不复制、格式化或导出正文。
3. 更新服务文件与 launcher。installer 会保留 env，不会访问 vault、修改笔记或立即重建索引。
4. 现有 env 若仍指定老索引，人工改为一个新的 v3 SQLite 路径。不要让新旧服务共享数据库。保持 embeddings=false，先验证关键词与治理流程。
5. 重启/重新连接全部客户端，确认 schema_version=3。未升级的旧客户端仍可能返回旧知识，不能宣称已全局生效。
6. 核对源文件摘要/mtime未改变；用 status 和 list 查看待复核数量。零 active 是正常起点。
7. 选择少量高价值主题，实时验证后按 admission 更新。明确不再适用的普通笔记标 deprecated；无法核实的继续 unreviewed。
8. 用相同真实问题对照关键词与可选混合检索，包含无答案、过时步骤、替代方案和跨 Agent 更新冲突。只有有明显收益才启用 embedding。

所有步骤都不能给受管文件补治理段、更新时间、链接或编码标记。该文件的唯一写入者是管理它的软件。

## 复核优先级

- 优先：真实项目入口、用户明确偏好、难重现故障的已证实教训、仍在用的维护步骤与决策原因。
- 必须重查：模型名、IP/域名、服务端口、部署方式、安装路径、工具版本、模拟器/设备标识、当前服务状态。
- 暂缓：重复课程摘要、整段会话总结、通用教程、无法定位依据的结论。人的资料可留在 Obsidian，暂不进入 Agent 默认背景。

## 已知边界

结构化门槛不能证明事实真实；历史访问仍需 Agent 遵守用途警告。此改版不会替用户删掉旧笔记或旧索引，也不会自动宣布某条操作已重新验证。旧索引中可能有敏感正文，按用户既有管理方式隔离处理。
